## 练习 7：自定义校验
```python
from pydantic import BaseModel, Field, field_validator

class UserRegister(BaseModel):
    username: str = Field(..., min_length=3, max_length=20)
    password: str = Field(..., min_length=6)

    @field_validator("password")
    @classmethod
    def check_password(cls, value: str) -> str:
        # TODO: 密码必须包含至少一个数字，否则 raise ValueError
        for c in value:
            if c.isdigit():
                return value
        raise ValueError
```

验证：
```python
UserRegister(username="zhangsan", password="abc123")  # 应该通过
UserRegister(username="zhangsan", password="abcdef")  # 应该报错
```

## 易错点：from_attributes 和 ValidationError

去掉 `from_attributes=True` 后，`UserOut.model_validate(ORMUser(...))` 会报：

```text
ValidationError
Input should be a valid dictionary or instance of UserOut
[type=model_type, input_type=ORMUser]
```

原因：Pydantic 默认要求 `model_validate()` 的输入是字典，或者已经是该模型本身的实例；它不会默认去读取任意对象的 `.id`、`.username` 等属性。

加上这个配置后，Pydantic 才会在输入不是字典时尝试用 `getattr(input, "字段名")` 读取属性：

```python
class UserOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    username: str
```

什么时候需要：
- 从 SQLAlchemy ORM 对象直接构造 Pydantic 模型
- 从 dataclass、namedtuple、普通自定义类读取属性

为什么 FastAPI 项目里有时不写也能跑：FastAPI 的 `response_model` 会把返回对象先转成 JSON 兼容数据，再交给 Pydantic 校验；而单独写 `model_validate(对象)` 时没有这层转换，必须显式开启 `from_attributes=True`。
