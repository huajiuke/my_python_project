# 第 9-10 周：Docker 部署 FastAPI + MySQL

## 一、Docker 核心概念

| 概念 | 说明 |
|------|------|
| 镜像 Image | 打包好的运行环境，不可变 |
| 容器 Container | 镜像运行后的实例 |
| Dockerfile | 描述如何构建镜像 |
| docker-compose | 用 YAML 编排多个容器 |
| Volume | 容器外的持久化数据目录 |

一句话理解：
> Dockerfile 是“菜谱”，镜像是一份“预加工食材”，容器是“端上桌的菜”。

## 二、项目新增文件

```text
fastApiProject/
├── Dockerfile            # FastAPI 镜像构建
├── docker-compose.yml    # MySQL + API 编排
├── .dockerignore         # 不复制进镜像的文件
└── .env.example          # 环境变量模板
```

## 三、Dockerfile 说明
```dockerfile
FROM python:3.12-slim

WORKDIR /app

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

COPY app/requirements.txt ./requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```
- `FROM`：基础镜像
- `WORKDIR`：容器内工作目录
- `COPY`：复制文件进镜像
- `RUN`：构建时执行命令
- `CMD`：容器启动时执行的命令

注意：
- `--host 0.0.0.0` 让容器外部可以访问
- 先复制 requirements 再装依赖，可以利用 Docker 缓存

## 四、docker-compose.yml 说明
```yaml
services:
  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
    volumes:
      - mysql_data:/var/lib/mysql

  api:
    build: .
    environment:
      DATABASE_URL: mysql+pymysql://${MYSQL_USER}:${MYSQL_PASSWORD}@db:3306/${MYSQL_DATABASE}
      SECRET_KEY: ${SECRET_KEY}
    ports:
      - "8000:8000"
    depends_on:
      db:
        condition: service_healthy

volumes:
  mysql_data:
```
- `db`：MySQL 8.0 容器
- `api`：FastAPI 容器，依赖 db 健康后才启动
- `mysql_data`：MySQL 数据持久化到 Docker Volume

## 五、数据库连接变化
开发环境：
```text
sqlite:///./app/data/fastapi.db
```

Docker 环境：
```text
mysql+pymysql://fastapi:fastapi123@db:3306/fastapi_db
```

代码无需修改：
- `app/config.py` 已经通过 `DATABASE_URL` 环境变量读取
- `app/database.py` 只对 SQLite 加 `check_same_thread`

## 六、运行命令
```bash
cd fastapi_learning/fastApiProject

# 1. 创建 .env
copy .env.example .env

# 2. 构建并启动
docker compose up --build -d

# 3. 查看日志
docker compose logs -f api

# 4. 停止
docker compose down

# 5. 删除数据卷（会清空数据库）
docker compose down -v
```

## 七、安全注意事项
- `.env` 不能提交到 Git
- `SECRET_KEY`、数据库密码都要改成自己的强密码
- 生产环境不要用 MySQL 8.0 默认认证插件时避免弱密码
- 数据库只对 Docker 内部网络暴露，外部访问再单独配置

## 八、实际运行记录

本机已完成 Docker Desktop + WSL2 + Ubuntu 安装，项目已经成功跑通。

### 1. Docker Hub 网络问题
第一次拉取 `mysql:8.0` 失败，错误是 Docker Hub 被解析到 IPv6 地址但无法连接。解决方式是在 Docker Desktop 的 `Settings -> Docker Engine` 配置镜像加速：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
```

### 2. 容器依赖问题
API 容器启动失败，日志显示：

```text
ModuleNotFoundError: No module named 'sqlalchemy'
```

原因是 `app/requirements.txt` 漏了 `SQLAlchemy`。补上之后又出现：

```text
RuntimeError: 'cryptography' package is required for sha256_password
```

MySQL 8 默认使用 `caching_sha2_password` 认证，PyMySQL 需要 `cryptography`。最终 `app/requirements.txt` 补齐：

```text
SQLAlchemy==2.0.51
greenlet==3.5.4
cryptography==44.0.0
PyMySQL==1.1.1
```

### 3. 最终启动命令
```bash
cd fastapi_learning/fastApiProject
copy .env.example .env
docker compose up --build -d
```
