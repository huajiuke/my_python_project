## 一、默认太宽松

Pydantic 默认会**忽略**多余字段，这恰好纵容模型编造字段：

```python
from pydantic import BaseModel, ConfigDict

class Loose(BaseModel):
    pass  # 多余字段被静默丢弃

class StrictModel(BaseModel):
    model_config = ConfigDict(extra='forbid')  # 多余字段直接报错
```

LLM 场景一律用 `extra='forbid'`：多出来的字段通常意味着**模型理解错了任务**，
让它报错重试比悄悄丢掉安全得多。

## 二、约束写在字段上

```python
from typing import Literal
from pydantic import Field

class NoteCard(StrictModel):
    title: str = Field(min_length=1, max_length=80)
    confidence: float = Field(ge=0.0, le=1.0)
    tags: list[str] = Field(default_factory=list, max_length=8)
    kind: Literal['fact', 'technique', 'motif']
```

三个要点：

- `Field(ge=..., le=...)` 让"取值范围"成为契约，而不是事后 if 判断
- `Literal` 比 `str` 好得多：枚举直接把可选值告诉模型，大幅降低跑偏率
- 列表字段用 `default_factory=list`，不要写 `= []`

## 三、JSON Schema 可以直接喂给模型

`model_json_schema()` 生成标准 JSON Schema，与函数调用的 `parameters` 格式一致：

```python
import json
print(json.dumps(NoteCard.model_json_schema(), ensure_ascii=False, indent=2))
```

嵌套模型会被放进 `$defs` 并用 `$ref` 引用——模型能读懂，但**嵌套越深通过率越低**。

## 四、五个常见坑

| 坑 | 后果 | 对策 |
|----|------|------|
| 有默认值却当成必填 | 模型省略该字段也校验通过 | 必填就不给默认值 |
| `Optional` 滥用 | 模型偷懒全填 null | 只有真的可空才用 |
| schema 嵌套太深 | 一次通过率骤降 | 拆成两次调用，先粗后细 |
| 中文字段名 | 部分模型与工具链处理不稳 | 字段名用英文，描述用中文 |
| 把校验错误直接抛给用户 | 无法定位 | 转成"字段路径 + 原因"的结构化问题 |
