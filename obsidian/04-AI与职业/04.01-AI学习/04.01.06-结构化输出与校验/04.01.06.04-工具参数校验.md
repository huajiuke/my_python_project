## 一、arguments 只是字符串

Function calling 返回的 `tool_calls[].function.arguments` 是 **JSON 字符串**，不是 dict。
`agent_learning/tool_calling_agent.py` 里已经能看到这一步转换：

```python
args = json.loads(call.function.arguments)   # 字符串 → dict
result = registry.call(call.function.name, args)
```

问题是：`json.loads` 只保证**语法合法**，不保证**参数可用**。
模型完全可能给出 `{"max_chars": -1}` 或 `{"path": 123}`。

## 二、两道闸门

| 闸门 | 管什么 | 实现 |
|------|--------|------|
| 参数校验 | **对不对**（类型、范围、必填、多余字段） | `validate_tool_arguments()` |
| 权限控制 | **能不能做**（只读/可写、白名单） | `RunContext` + `ToolRegistry` |

顺序很重要：**先校验参数，再判权限**——参数都不合法，没必要谈授权。

## 三、用法

```python
from pydantic import Field
from agent_learning.structured_output import StrictModel, validate_tool_arguments

class ReadFileArgs(StrictModel):
    path: str = Field(min_length=1)
    max_chars: int = Field(default=4000, ge=1, le=20000)

arguments = validate_tool_arguments(ReadFileArgs, call.function.arguments)
content = read_text_file(arguments.path, arguments.max_chars)
```

失败的 `ToolArgumentError` 消息形如 `max_chars: Input should be less than or equal to 20000`，
可以直接作为 Observation 回填给模型，比抛栈更容易被模型自我修正。

## 四、schema 从模型生成

`to_tool_schema()` 直接由 Pydantic 模型生成函数 schema，
**校验规则与暴露给模型的 schema 同源**，不会出现"文档写 1-20000、代码却允许负数"的漂移：

```python
from agent_learning.structured_output import to_tool_schema

schema = to_tool_schema('read_text_file', '读取工作区内文本文件', ReadFileArgs)
```

## 五、安全视角

模型给出的参数属于**不可信输入**，与用户输入同级：

- 路径类参数要做根目录约束（参考 `_is_relative_to`），类型校验只是第一层
- 数量、长度上限写进 schema，别只靠代码兜底
- 未知字段直接拒绝，避免"多传一个字段"触发未预期的分支
