# 面试要点

> 上级：[[04-AI与职业/04.01-AI学习/04.01.06-结构化输出与校验/04.01.06-结构化输出与校验|04.01.06-结构化输出与校验]]

### Q1: 怎么保证 LLM 输出是结构化且可靠的？

思路：四层——把 JSON Schema 交给模型做约束；用括号配对扫描从噪声里提取 JSON；用 Pydantic 严格模型（`extra='forbid'`）判定合规；失败时把"具体哪个字段错"回喂重试，重试仍失败就抛错。核心是校验失败绝不靠猜兜底。

### Q2: 模型输出不是合法 JSON 怎么办？

思路：先容忍再严格。模型常在 JSON 外面包代码块和解释文字，所以先做提取（扫描第一个完整对象，跳过字符串内的花括号），再 `json.loads`；解析失败就把错误位置（行/列）作为问题回喂。不要用正则硬切。

### Q3: 为什么要禁止多余字段？

思路：多余字段通常意味着模型误解了任务。默认行为是静默丢弃，错误被埋进数据；`extra='forbid'` 让它变成显式失败，一次重试即可修正，比事后排查便宜。

### Q4: 重试提示词怎么写才有效？

思路：必须具体——字段路径 + 校验原因 + 上次原始输出。笼统说"格式不对"会让模型重复犯错。同时把 `max_attempts` 控制在 2-3 次，避免成本失控。

### Q5: 工具调用怎么防错？

思路：两道闸门，先校验参数（类型、范围、必填、多余字段），再判权限（只读/可写、白名单）。参数 schema 由模型类生成，保证"给模型看的"和"代码校验的"同源，避免规则漂移。路径类参数还要额外做根目录约束。

### Q6: 结构化输出和上下文工程怎么配合？

思路：schema 文本也消耗 token，要计入预算；字段越多、嵌套越深，一次通过率越低、重试成本越高。所以 schema 要精简，复杂任务拆成"先粗后细"两次调用。
