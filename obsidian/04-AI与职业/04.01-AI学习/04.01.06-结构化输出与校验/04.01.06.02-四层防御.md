## 一、四层各管一件事

| 层 | 作用 | 实现 |
|----|------|------|
| schema 约束 | 提前告诉模型字段与类型 | `schema_instruction()` |
| 提取 | 从带噪声的输出里取出 JSON | `extract_json_object()` |
| 严格校验 | 判定是否真的合规 | `StrictModel` + Pydantic |
| 修复重试 | 把错误回喂再试 | `structured_call()` |

四层缺一不可：只约束不校验等于没防线；只校验不修复，成功率白白损失。

## 二、提取为什么不能只用 json.loads

模型的常见输出：

``````
好的，结果如下：
```json
{"title": "摘要", "confidence": 0.8}
```
以上。
``````

`extract_json_object` 用**括号配对扫描**：从第一个 `{` 开始计深度，
跳过字符串内部的花括号与转义引号，深度归零即结束。比正则可靠，因为它理解嵌套。

## 三、修复重试的关键：错误要具体

| 回喂提示 | 效果 |
|----------|------|
| "格式不对，请重新输出" | 模型基本瞎猜，容易再错 |
| "confidence: Input should be a valid number；mood: Extra inputs are not permitted" | 模型能精确修正 |

所以重试消息必须带：**字段路径 + 具体原因 + 上次原始输出**。

## 四、用法

```python
from pydantic import Field
from agent_learning.structured_output import StrictModel, structured_call

class NoteCard(StrictModel):
    title: str
    confidence: float = Field(ge=0.0, le=1.0)
    tags: list[str] = Field(default_factory=list)

response = structured_call(
    llm, NoteCard,
    [{'role': 'user', 'content': '把这段笔记抽成卡片：……'}],
    max_attempts=3,
)
print(response.value.title, response.attempts)
```

## 五、失败时要能查

重试仍失败就抛 `StructuredOutputError`，它带三样东西：

| 属性 | 用途 |
|------|------|
| `attempts` | 试了几次 |
| `issues` / `issue_text()` | 最后卡在哪些字段 |
| `raw_outputs` | 每次的原始输出，用于复盘 prompt |

**不要吞掉原始输出**——那是改进 prompt 的唯一线索。

## 六、成本意识

重试 = 多一次调用。所以：

- `max_attempts` 默认 3 足够，别设 10
- schema 越简单，一次通过率越高（字段少、嵌套浅）
- 反复出错的字段改成可选，或让模型标注不确定度
