# 基线与回归对比

> 上级：[[04-AI与职业/04.01-AI学习/04.01.08-评估与回归/04.01.08-评估与回归|04.01.08-评估与回归]]

## 一、报告要能存下来

想把"和上次比"变成命令，前提是上次的结果能被读出来。
`EvalReport` 的 `save` / `load` 走 JSON（`ensure_ascii=False`，中文直接可读）：

```python
report = run_suite(cases, runner)
report.save('agent_learning/data/eval_baseline.json')
previous = EvalReport.load('agent_learning/data/eval_baseline.json')
```

报告逐条存 `case_id / passed / failures / answer / tool_calls / tokens`。
存 `answer` 有争议（占空间），但**定位回归时必须看它**——
"这条上次还通过，为什么这次挂了"，不看原答案只能猜。

## 二、对比只有三种结论

以 `case_id` 为键，把当前报告和基线对一遍：

| 变化 | 名称 | 含义 |
|------|------|------|
| 上次通过 → 这次失败 | **回归** | 必须立刻处理，这是评估的核心价值 |
| 上次失败 → 这次通过 | 改进 | 确认这次改动真的有效 |
| 基线里没有 | 新增用例 | 既不算回归，也不算改进 |

把新增用例单独成一类很重要：新写的用例一上来就失败是正常的，
如果不区分，它会被误报成"回归"，噪声淹没真问题。

## 三、一行命令跑完

```python
report, comparison = run_and_compare(
    cases,
    runner,
    report_path='agent_learning/data/eval_baseline.json',
)
print(comparison)
```

`run_and_compare` 做三件事：跑一轮 → 读旧报告对比 → **把新报告写回同一路径**。
写回是关键：下一次对比的就是这一次，基线自动前移，不用手动管理版本号。

`compare` 的输出形如：

```
通过 12/14（86%） 失败 2 总 token 8421 | 基线 通过 13/14（93%）...
| 回归: session-lifecycle | 改进: 无 | 新增用例: citation-format
```

## 四、几个坑

- **基线和用例集必须同源**。删了某条用例却没重新生成基线，
  对比时它会静默消失，看起来"没有回归"；
- 基线文件**要么进版本控制、要么作为 CI 产物存档**，换台机器没有基线就等于没评估；
- 对比只看 `passed` 布尔值，不看答案差异。答案从"勉强通过"变成"讲得很清楚"
  不会有任何提示，想看这种质量提升只能靠**加严 `must_include`**。
