# 分层组装与优先级裁剪

> 上级：[[04-AI与职业/04.01-AI学习/04.01.05-上下文工程/04.01.05-上下文工程|04.01.05-上下文工程]]

## 一、五层结构

用 `ContextLayer` 描述每一层：

| 层 | priority | drop_from | mandatory | 理由 |
|----|----------|-----------|-----------|------|
| system 系统提示 | 0 | — | 是 | 角色与规则不能缺 |
| summary 历史摘要 | 1 | tail | 否 | 越旧越不重要 |
| recent 最近对话 | 2 | head | 否 | 丢最旧的，保最新 |
| retrieved 检索片段 | 3 | tail | 否 | 已按相关度排序，先丢最不相关 |
| observation 工具输出 | 4 | tail | 否 | 最该被压缩的一层 |

**裁剪方向（`drop_from`）由排序依据决定**：

- 按**相关度**排序 → 从尾部丢（`tail`）
- 按**时间**排序 → 从头丢（`head`）

搞反了就会丢掉最新或最相关的信息，这是最容易犯的错。

## 二、裁剪算法

1. `usable = budget_tokens - reserve_output_tokens`
2. 按 priority 从大到小裁剪（低优先级先丢）
3. 每层按 `drop_from` 从一端丢片段，直到装得下
4. `mandatory` 层跳过；仍装不下时报告 `overflow_tokens`

设计要点：

- **mandatory 层永不裁剪**，超预算时由调用方决定（换模型 / 压缩系统提示）
- 裁剪粒度是"整片段"，不截半个片段，避免语义残缺
- 单个片段本身过长时，先用 `truncate_to_tokens` 压进预算

## 三、用法

```python
from agent_learning.token_budget import ContextLayer, plan_context

plan = plan_context(
    [
        ContextLayer(name='system', priority=0, segments=(SYSTEM_PROMPT,), mandatory=True),
        ContextLayer(name='summary', priority=1, segments=(summary,) if summary else ()),
        ContextLayer(name='recent', priority=2, segments=history, drop_from='head'),
        ContextLayer(name='retrieved', priority=3, segments=snippets),
    ],
    budget_tokens=8000,
    reserve_output_tokens=1200,
)

prompt = plan.render()
print(plan.report.summary())
# tokens=5120/6800 overflow=0 system=48/48 summary=1180/1180 recent=1990/3200 retrieved=1902/4200
```

`summary()` 每一段格式是 `层名=保留token/原始token`，
一眼看出谁被裁、裁了多少——比日志里写"历史已压缩"有用得多。

## 四、估算与真实的区别

`estimate_tokens` 是无 tokenizer 的近似（中文 1 字≈1 token、英文 4 字符≈1 token），
取值偏保守。它负责**本地预算决策**；真实计费看 API 的 `usage`，
并定期对账校准。详见 [[04-AI与职业/04.01-AI学习/04.01.05-上下文工程/04.01.05.04-Prompt缓存与成本度量|Prompt 缓存与成本度量]]。

## 五、验证点

`agent_learning/test_token_budget.py` 覆盖：

- 预算充足时不做任何裁剪
- 低优先级层先被丢
- `drop_from='head'` 时保留最新片段
- mandatory 层超预算时正确报告 overflow
- `reserve_output_tokens` 正确压缩可用预算

## 面试怎么答

> 问：上下文塞不下时你丢什么？
> 答：按可丢弃性排序——系统提示和当前问题不可丢，旧对话进摘要，检索片段按相关度从尾部丢，最近对话从头部丢。方向由排序依据决定，不能拍脑袋。同时必须预留输出空间。
