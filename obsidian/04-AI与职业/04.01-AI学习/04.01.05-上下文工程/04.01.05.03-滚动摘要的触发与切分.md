# 滚动摘要的触发与切分

> 上级：[[04-AI与职业/04.01-AI学习/04.01.05-上下文工程/04.01.05-上下文工程|04.01.05-上下文工程]]

## 一、现状

`note_qa_agent.py` 目前的三个参数：

| 参数 | 默认 | 作用 |
|------|------|------|
| `max_history_rounds` | 10 | 拼进 prompt 的最近轮数 |
| `summary_trigger_rounds` | 10 | 完成多少轮后触发摘要 |
| `max_summary_chars` | 2000 | 摘要字符上限 |

`conversation_summarizer.py` 的 `summarize(previous_summary, messages)` 负责合并压缩。

## 二、三个问题

1. **触发时机不可控**：10 轮可能是 200 字，也可能是 3 万字，后者直接爆预算
2. **上限用字符**：中文 2000 字符 ≈ 2000 token，混排时说不清
3. **没有下限保护**：理论上可能把正在进行的一轮也摘要掉

## 三、改法

**触发用 token，不用轮数**：

```python
from agent_learning.token_budget import estimate_message_tokens, split_for_summary

if estimate_message_tokens(self.history) > self.summary_trigger_tokens:
    older, recent = split_for_summary(
        self.history, keep_tokens=self.recent_history_tokens
    )
    summary = self.summarizer.summarize(self._summary, older)
    self.history = recent
```

**切分保证下限**：`split_for_summary` 从最新一条往前累计，装到 `keep_tokens` 为止，
且至少保留 `min_keep` 条（默认 1），正在进行的一轮绝不会被摘要掉。

**两个阈值分开配**：

| 参数 | 作用 |
|------|------|
| `summary_trigger_tokens` | 超过就压缩（触发线） |
| `recent_history_tokens` | 压缩后保留的最近对话 token 数（保留线） |

## 四、摘要的取舍规则

摘要是有损压缩，**必须留**：

- 用户目标与偏好（"用中文""不要表格"）
- 已确认的事实与结论（避免反复确认）
- 未解决的问题（否则被遗忘）
- 重要约束（路径、版本、命名）

**可以丢**：寒暄、重复内容、已被推翻的中间结论、工具调用的原始输出。

## 五、摘要不能替代检索

| | 滚动摘要 | 检索 |
|--|---------|------|
| 覆盖 | 全部旧对话 | 只取相关片段 |
| 精度 | 低（模糊） | 高（原文） |
| 成本 | 一次性压缩 | 每次检索 |
| 适合 | 对话脉络 | 事实、代码、结论原文 |

**结论性内容应当以原文进检索库，而不是只留在摘要里**——摘要是索引，不是档案。
