# Prompt 缓存与成本度量

> 上级：[[04-AI与职业/04.01-AI学习/04.01.05-上下文工程/04.01.05-上下文工程|04.01.05-上下文工程]]

## 一、缓存命中靠"前缀完全一致"

主流实现都是**前缀缓存**：从第一个 token 开始逐段比对，一旦不同就停止复用。

所以拼接顺序直接决定成本：

```
[稳定]   system prompt + 工具 schema + 固定规则
[半稳定] 长文档 / 历史摘要
[变化]   检索片段 → 最近对话 → 用户提问
```

把变化的内容放到前面，缓存永远不命中。

## 二、四个常见错误

- system prompt 里插当前时间戳 → 前缀每次都变，缓存全废
- 把检索结果拼在系统提示之前 → 前缀不稳定
- 工具 schema 顺序漂移（字典迭代顺序、动态注册）→ 前缀抖动
- 每轮无条件拼接全部历史、不用摘要 → 输入 token 线性增长

## 三、该度量什么

| 指标 | 用途 |
|------|------|
| `usage.prompt_tokens` / `completion_tokens` | 真实计费与预算校准 |
| 缓存命中 token 数 | 判断前缀是否稳定 |
| 各层 token 占比（`plan.report.summary()`） | 定位是谁吃掉了预算 |
| 单次 / 单章成本 | 决定用哪个档位的模型 |
| 估算误差（估算 vs usage） | 校准 `estimate_tokens` 系数 |

## 四、估算与真实对账

```python
estimated = plan.report.total_tokens
actual = response.usage.prompt_tokens
ratio = actual / estimated   # 记录并观察，长期接近 1 才说明估算可用
```

分工要清楚：**估算负责决策**（这一轮装不装得下），**usage 负责记账**（这轮花了多少）。
两者都记，否则要么超预算，要么白省成本。

## 五、一句话总结

> 稳定在前、变化在后；前缀不动则缓存命中；估算决策、usage 记账。
