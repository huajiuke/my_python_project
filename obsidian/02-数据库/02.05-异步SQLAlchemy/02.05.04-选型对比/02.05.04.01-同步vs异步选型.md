# 同步 vs 异步选型

> 上级：[[02-数据库/02.05-异步SQLAlchemy/02.05.04-选型对比/02.05.04-选型对比|02.05.04-选型对比]]

## 不是独立的库

异步 SQLAlchemy 不是另一个 ORM，而是 SQLAlchemy 2.0 自带的 asyncio 扩展（`sqlalchemy.ext.asyncio`）。模型、查询、关系定义与同步版同一套，差异集中在引擎、会话和 IO 层。

## 核心区别

| 维度 | 同步 SQLAlchemy | 异步 SQLAlchemy |
|------|----------------|----------------|
| 引擎 | `create_engine` | `create_async_engine` |
| 会话 | `Session` / `sessionmaker` | `AsyncSession` / `async_sessionmaker` |
| 数据库调用 | 直接执行，阻塞线程 | 全部 `await` |
| 驱动 | pymysql、psycopg2、sqlite3 | aiosqlite、asyncpg、aiomysql |
| 懒加载 | 自动可用 | 不可隐式懒加载（`MissingGreenlet`） |
| 关系访问 | `user.posts` | 预加载或 `await user.posts`（AsyncAttrs） |
| 事务 | `session.commit()` | `await session.commit()` |
| 提交后属性 | 默认 `expire_on_commit=True` | 推荐 `False` |

## 性能本质

异步不是更快，而是在等待数据库时让出事件循环，让同一进程同时处理更多请求，减少线程和连接占用。单请求延迟两者差别不大。

## 工程选型

实际工程中同步更常见、更成熟：

- 存量项目、管理后台、数据脚本、Django/Flask 体系
- 调试简单，异常链路直观
- 与 Celery、同步库混用没有割裂感

异步在新一代 FastAPI 服务中越来越主流：

- 新项目、纯异步技术栈
- 高并发 I/O 密集场景
- PostgreSQL + asyncpg
- 与 httpx、WebSocket、异步任务保持一致

## 务实建议

- 老项目或团队不熟异步：继续用同步
- 新 FastAPI 项目：可以从异步开始，默认 `expire_on_commit=False`，禁用隐式懒加载
- 模型层几乎一样，后续迁移成本可控
